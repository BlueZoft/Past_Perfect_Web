## Verification boundaries

The v3.0 release recorded **94 backend tests**, **75 frontend tests**, and successful Vite production build. Evidence is in the source [web tests](../../src/test/local-completion.test.jsx), [API tests](https://github.com/BlueZoft/Past_Perfect_BackEnd/blob/master/test/local-completion.test.js) and [release history](../releases/history.md). CI workflows are configured; their existence is not evidence that a hosted run succeeded.

For this documentation revision, validate links, source paths, public route names, topic navigation and current-versus-historical claims. Application tests need not be rerun for prose/link relocation alone. No manual browser/device/contrast/native-language validation, live SMTP/Cloudinary/payment/carrier integration, production throughput assessment or deployment is claimed by this audit.

## Keep the docs accurate

When changing behavior, update the relevant user guide and workflow, then backend contract/configuration where applicable. Change release history only as history, not as the main current user guide. Record a new audit baseline when runtime claims are rechecked. Keep old filename redirects for externally shared links and update hubs/README navigation when moving a page.
